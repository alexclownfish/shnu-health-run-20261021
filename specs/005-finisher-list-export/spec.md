# Feature Specification: 管理员按需导出完赛名单

**Feature Branch**: `theme/warm-orange-indigo`（沿用；MVP 代码与文档）
**Created**: 2026-10-09
**Status**: MVP implementation authorized on 2026-10-09; live provisioning requires real environment configuration
**Input**: 新增完赛人员名单 Excel 导出，无参与者管理入口；批准 MVP 实施，隔离开发测试数据并提供云函数建立步骤。

## User Scenarios & Testing

### User Story 1 - 汇集完赛名单 (Priority: P1)

组织者可以取得不同手机上的完赛人员记录，参与者沿用起点、任务点、终点和凭证流程。

**Why this priority**: 没有集中记录，就没有全体人员名单可导出。
**Independent Test**: 两个不同参与账号分别完赛，组织者可取得两条相互独立的记录。

**Acceptance Scenarios**:

1. **Given** 参与者完成起点、全部任务点及终点，**When** 完赛记录提交成功，**Then** 对应活动名单包含该参与者一次。
2. **Given** 同一参与者多次打开凭证或重复提交，**When** 组织者查询，**Then** 每次活动仍只有一条完赛人员记录。
3. **Given** 参与者尚未扫描终点，**When** 导出，**Then** 名单不包含该未完赛记录。

### User Story 2 - 电脑按需导出 (Priority: P1)

管理员在电脑上选择活动导出 Excel，小程序无需提供管理页面。

**Why this priority**: 满足活动组织者实际使用方式，无需开发参与者可见的管理入口。
**Independent Test**: 授权管理员取得指定活动名单，普通参与者无法取得别人的名单。

**Acceptance Scenarios**:

1. **Given** 活动存在有效记录，**When** 管理员导出，**Then** 文件包含昵称、开始时间、完成时间、总用时及必要的活动与参与者编号。
2. **Given** 补交窗口已关闭且记录跨多页，**When** 最终导出，**Then** 导出截止时刻已收到的有效记录全部出现，无遗漏或重复；进行中预览注明尚有未收到/处理中记录。
3. **Given** 无完赛记录，**When** 导出，**Then** 文件保留表头并明确记录数为零。
4. **Given** 未授权人员尝试读取名单，**When** 请求处理，**Then** 被拒绝，即使其知道管理入口或操作名称。

### User Story 3 - 网络异常后恢复 (Priority: P2)

网络异常不会阻止本地完赛与凭证生成，具备网络后可以补交名单记录。

**Why this priority**: 活动现场网络故障不能破坏现有打卡体验。
**Independent Test**: 离线完赛，保持本地记录，恢复网络并重进小程序后补交一次。

**Acceptance Scenarios**:

1. **Given** 完赛时断网，**When** 打开凭证，**Then** 本地凭证仍可查看并保存，完赛摘要保留为待提交。
2. **Given** 提交已成功但响应丢失，**When** 再次提交，**Then** 名单不产生重复行。
3. **Given** 待提交完赛记录存在，**When** 重置路线，**Then** 待提交摘要保留；清除小程序全部数据仍可能丢失未提交记录。

### Edge Cases

- 昵称缺失、重名或修改：用稳定参与者编号区分，昵称不充当真实姓名。
- 修改手机时间、复制二维码或篡改本地数据：汇总名单不等于可信成绩或真实到场证明。
- 多次活动、路线更换或任务数变化：记录包含活动和路线版本，不能混入其他活动。
- 导出过程中新增记录：进行中预览不是数据库事务快照；最终名单在补交窗口关闭至少一分钟后取得。
- 历史版本没有上报记录：不得声称可以从管理员电脑直接恢复其他手机的数据。
- 昵称含特殊字符或类似公式文本：导出后仍是文本，不能作为表格公式执行。

## Requirements

### Functional Requirements

- **FR-001**: 名单 MUST 汇集不同参与者已成功提交的完赛摘要。
- **FR-002**: 全部参与者页面 MUST 不包含名单、导出按钮或管理入口；管理读取权限独立验证。
- **FR-003**: 仅满足现有起点、全部任务点和终点条件的本地记录可自动提交。
- **FR-004**: 每个活动每个参与账号最多保留一条完赛名单记录，默认保留首条成功接收记录。
- **FR-005**: 导出 MUST 支持按活动筛选，展示昵称、起止时间和总用时，无排名要求。
- **FR-006**: 普通参与者不得读取其他人的摘要或直接改写完赛名单。
- **FR-007**: 网络失败不得阻止本地打卡和凭证，必须保留待提交摘要并在后续启动/恢复页面时重试。
- **FR-008**: 只收集名单所需的最小摘要，不收集照片、头像、二维码 token 或扫码原文。
- **FR-009**: 导出必须注明活动、记录数、截止时间和“已收到的完赛记录”口径。
- **FR-010**: 起止时间和总用时仍来自参与者手机；接收时间单独记录，不混同为完成时间。
- **FR-011**: 每次活动必须有独立活动标识和明确路线版本，当前路线编号不能代替活动编号。
- **FR-012**: 增加集中收集后必须同步更新实际数据使用说明，不能继续声称所有记录均仅在本机。
- **FR-013**: 开发版/体验版默认走测试云环境，正式版走生产环境；两个环境 ID 不能相同，生产名单默认排除测试记录。
- **FR-014**: 云端独立配置活动、路线、正式开始/结束时间、补交截止及开发账号排除名单，不相信客户端的 isTest/admin 标记。
- **FR-015**: 只有在新版起点开始时绑定活动上下文的本次终点记录可上报，历史缓存或旧测试凭证不得自动回填。
- **FR-016**: 未配置环境或活动默认关闭收集；正式导出必须校验环境、活动版本、时间、唯一身份和结构，脏行报告数量并排除。
- **FR-017**: 开发与正式目标 MUST 具有独立启用开关；本轮仅开发版/体验版可上报，正式版即使已有环境 ID 和活动 ID，也不得初始化或提交名单请求。
- **FR-018**: 管理员可从已授权控制台导出完整 JSON，再在本地转换为 .xlsx；本地模式不得读取密钥或访问云端，仍应用活动、环境、结构、时间、去重与测试隔离规则，并注明输入文件的统计边界。

### Key Entities

- **活动**: 独立活动标识、名称、路线版本、开放与补交期限。
- **完赛摘要**: 活动、稳定参与者编号、昵称快照、起止时间、用时、完成点位、接收时间。
- **待提交摘要**: 本地完赛时冻结的摘要和重试状态，独立于可重置的路线进度。
- **管理员**: 有名单读取和导出权限的组织者。
- **导出文件**: 指定活动及截止时刻的完赛名单快照。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 有效终点记录成功接收后在对应活动导出中出现一次；测试中重复提交零重复行。
- **SC-002**: 未完赛记录和未授权名单读取的测试全部拒绝。
- **SC-003**: 跨多页样本导出与截止时刻已接收记录集合完全一致。
- **SC-004**: 断网时本地凭证仍可生成，恢复网络并重进后待提交样本补交成功。
- **SC-005**: Excel 正确显示中文、缺失姓名、超过 24 小时用时、空名单及类似公式的姓名文本。

## Assumptions

- 本次解释为导出全体参与者名单；只导出管理员自己手机的数据不满足需求。
- 第一版人员名称为用户在扫码前手动填写的参与者姓名；工号/报名表关联不属于本轮默认范围。
- 按活动每账号一行，不提供多圈成绩、排名、防作弊或跨设备路线恢复。
- 用户已批准 MVP 代码，并提供开发、正式两个云环境 ID，已填入配置；正式活动 ID、时间、排除账号和管理员凭据未提供，本次不创建收费云资源或部署到真实活动。
- 用户要求先完成开发环境。开发联调窗口采用 2026-10-09 00:00 至 2026-11-09 00:00，补交至 2026-11-10 00:00（Asia/Shanghai），可按实际测试安排改动；正式部署延后。开发云部署已授权，但当前工具访问受服务端口和电脑控制权限限制。
- 未补交且用户不再打开小程序的离线记录不会自动出现在名单；管理员不能得知其手机仍有几条待提交记录。
- 收集范围及保留期限需要在活动上线前确定并落实；导出入口不可见不意味着数据收集可以隐瞒。
