# Feature Specification: 二维码使用提示

**Feature Branch**: `theme/warm-orange-indigo`
**Created**: 2026-10-13
**Status**: Approved for implementation
**Input**: 用户选择“提示文字＋现有数据”，指定提示为“请在微信小程序「悠湃体育」内点击“扫码打卡”使用。”并授权实现。

## User Scenarios & Testing

### User Story 1 - 外部扫码看到使用指引 (Priority: P1)

参与者误用相机、微信扫一扫或支付宝扫一扫时，二维码读出的内容先包含指定使用提示，帮助其转到小程序内打卡。

**Why this priority**: 提示直接解决用户不知道应在哪里扫码的问题。
**Independent Test**: 解码起点、三个任务点和终点五张新图片，确认第一行逐字相同、第二行仍是对应的原点位数据。

**Acceptance Scenarios**:
1. 扫描任意新版二维码，读出完整提示和原点位数据；能显示文本的软件有机会展示该提示。
2. 五个点位都有新的可打印图片和制作原文，无需组织者手动修改点位信息。

### User Story 2 - 新旧码都能完成当前点位 (Priority: P1)

使用新版小程序，参与者可扫描新版带提示的二维码，也可在过渡期间扫描原二维码，继续同一活动。

**Why this priority**: 更新二维码不能中断现有活动或改变计时流程。
**Independent Test**: 对五个点位分别验证新旧码和两种常见换行，确认只有当前点位成功；错误或额外内容被拒绝。

**Acceptance Scenarios**:
1. 新旧两种二维码对应当前点位时得到相同打卡结果。
2. 其他点位、未知点位数据、错误提示、额外行和重复登记都不会产生成功打卡。
3. 成功后原有拍照、起终点计时、凭证及完赛摘要流程继续工作。

### Edge Cases

- 扫码软件可能不显示文本，或以自己的界面显示全部原文；不承诺控制其展示。
- 旧体验版不支持新格式，必须先更新小程序再替换标牌。
- 常见换行差异可以兼容；任意插入的提示、多个点位行不能被忽略。
- 外部扫码仍能读取和复制内容，提示不承担防复制功能。

## Requirements

### Functional Requirements

- **FR-001**: 五张新版二维码第一行必须为“请在微信小程序「悠湃体育」内点击“扫码打卡”使用。”，第二行是原点位数据。
- **FR-002**: 保留原五个点位的身份和顺序，并在新版小程序中兼容原二维码。
- **FR-003**: 只接受约定格式、唯一登记且属于当前点位的二维码，错误输入不推进活动。
- **FR-004**: 兼容常见换行表示，拒绝修改后的提示、额外数据行及拼接码。
- **FR-005**: 提供五张可打印图片及对应制作原文，生成的图片可被独立读取并确认内容。
- **FR-006**: 本次只增加扫码引导，不改活动标识、云环境、路线、现有页面主题及完赛数据内容。
- **FR-007**: 小程序本地完成二维码识别，无需增加服务或联网校验。

### Key Entities

- **点位二维码**: 原点位身份、新版展示内容和兼容的旧内容。
- **制作资料**: 各点位的图片与完整文本，来自同一登记清单。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 五张新版图片全部能读出指定提示及各自正确的原数据。
- **SC-002**: 五个点位的新旧码都能在正确阶段成功，其余阶段都被拒绝。
- **SC-003**: 格式错误、未知、重复登记、额外行的验证场景全部被拒绝。
- **SC-004**: 原有顺序、拍照、计时和完赛流程回归通过。

## Assumptions

- 用户本轮给出的“悠湃体育”仅用于二维码提示，不授权全站改名。
- 外部软件决定显示方式；验收区分二维码读出的原文和软件是否显示该原文。
- 现场二维码由组织者换印，小程序更新由组织者上传体验版。
