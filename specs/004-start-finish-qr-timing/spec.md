# Feature Specification: 起终点扫码计时

**Date**: 2026-10-01
**Working Branch**: `theme/warm-orange-indigo`
**Input**: 在三个任务点之前新增起点、之后新增终点；起点扫码成功开始计时，终点扫码成功结束计时；继续完全纯前端。
**Extends**: `002-in-app-nfc-checkin` 全平台扫码契约，保留 `003` 暖橙靛蓝主题和凭证仅显示完成时间、总用时的要求。

## User Stories

1. 未开始时，路线列表显示起点、三个锁定任务点和锁定终点。只有起点二维码成功匹配才开始计时；进入页面不会启动计时。
2. 起点完成后依次扫描三个任务点并拍照上传。任务点仍为三个，起终点不增加拍照任务。
3. 第三个任务点完成后仍在计时，终点解锁。终点二维码成功后固定结束时间，允许查看、保存完赛凭证。

## Requirements

- FR-001: 顺序为起点 `000` -> 任务点 `001/002/003` -> 终点 `999`，其他阶段的二维码必须拒绝。
- FR-002: 五个完整 HRQ1 文本直接登记在 `utils/qr-tags.js`，原三个任务点 payload 不变。
- FR-003: 开始和结束时间分别只写入一次，重进页面、重扫和重复回调不能重置时间。
- FR-004: 总用时为终点成功时间减起点成功时间，包含行进、停留、拍照和后台停留时间，不依赖页面倒计时。
- FR-005: 三个任务点完成不等于完赛，凭证和完整路线徽章必须以终点成功为前提。
- FR-006: 延续原生扫码页临时隐藏处理，卸载后的迟到回调、错码、取消、相机拒绝均不能推进。
- FR-007: 使用本机时间和 storage，不引入后端、数据库、NFC、平台分支或排名；不承诺防篡改、跨设备恢复或正式成绩。
- FR-008: 旧版起止时间无法证明起终点扫码，使用独立 v3 进度；不删除旧 v2 存储，但新页面不展示旧进度。

## Acceptance

- 未扫起点扫描任务点/终点不得成功；已完成 0/1/2 个任务点扫描终点均拒绝。
- 第三个点位照片上传后 `completed === 3`，但 `completedAt === 0` 且凭证不可用。
- 起点和终点完成后，凭证与相册海报显示固定完成时间、总用时，不显示距离或排名。
- 关闭、重开小程序后保持进度，重复扫描不重置时间；重置路线后才能开启新一次流程。
- 三个平台真机验证保留为发布前检查，自动化模拟通过不等于真机认证。
