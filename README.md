# 悠湃体育健康打卡小程序

项目包含：

- `ui-prototype/`：之前完成的 H5 UI 原型，打开 `ui-prototype/index.html` 即可预览。
- `miniprogram/`：微信原生小程序源码，导入项目根目录到微信开发者工具即可运行。
- `cloudfunctions/submitCompletion/`：完赛摘要云函数，分别部署到测试和正式云环境。
- `tools/export-finishers/`：管理员电脑按需导出 Excel，无小程序管理入口。

## 导入方式

使用微信开发者工具打开当前仓库根目录，工具会读取 `project.config.json` 的 `miniprogramRoot` 配置。项目已配置正式 AppID，上传前需在开发者工具中登录拥有该小程序权限的微信账号。

## 已实现流程

路线首页 -> 扫描起点并开始计时 -> 依次扫描三个任务点二维码、拍照上传 -> 扫描终点并结束计时 -> 完赛凭证。活动总里程为 3.50 km；地图轨迹仍来自 2026-10-11 的两步路 KMZ，三个任务点均只需扫码后拍照上传。所有平台使用同一套二维码入口，也不接受任意二维码作为成功依据。

进度、起止时间和照片路径使用本地 storage 保存。`wx.chooseMedia` 已接入真实相机/相册入口，选择后的照片通过 `wx.saveFile` 持久保存在当前手机，不会上传到自建后端或云存储，也不会跨设备同步。项目使用小程序 AppID `wx9d16b2e04851fc36`。头像与昵称使用微信授权控件，记录页日历基于系统日期动态生成。

路线卡片使用微信原生 `<map>` 加载真实底图，357个轨迹点按原67/290点两段绘制，不连接录制间隙；起点、三任务点、终点使用原生marker。任务标记使用KMZ的精确标注坐标，起终点取轨迹首尾，S/F标签错开显示。规范化资料在 `utils/route-20261011.js`，`route.js` 按标准KML的WGS84转换为GCJ-02；源文件未明确声明坐标系，仍需现场核对。维护方法见 [新路线联调说明](specs/007-route-maintenance/quickstart.md)。

## 点位打卡配置

当前本地路线进度决定唯一待完成点位，二维码校验不请求远程接口，只证明读取到的标记属于该点位。名单上报仅在开启的目标环境中成功终点后提交摘要，不将打卡校验迁至云端。当前测试版和正式版均已配置上报，发布前按活动窗口联调。

### 点位二维码

二维码清单位于 `miniprogram/utils/qr-tags.js`。2026-10-13起，新打印二维码使用两行纯文本：

```text
请在微信小程序「悠湃体育」内点击“扫码打卡”使用。
HRQ1|001|QR-001-A|<随机token>
```

新版小程序兼容旧的单行HRQ1二维码，也接受固定提示加LF/CRLF换行的新版码；不会从任意文本中提取点位数据。先更新并上传小程序，再替换标牌，旧体验版不能识别新格式。其他扫码软件能够读取完整内容，但是否展示文字由软件决定。本次提示名称和页面品牌统一为“悠湃体育”。

运行`npm run generate:qr-tags`从当前清单生成五张黑白PNG、五份UTF-8原文及制作说明。图片位于`assets/qr-checkpoints/`，发布与验收见[二维码使用提示](specs/008-qr-usage-guidance/quickstart.md)。旧`provisioning-manifest.csv`仅保留历史制作资料，最新打印内容以生成的清单为准。

二维码应印在起点、三个任务点和终点标牌上。所有平台用户先打开小程序，再点击“扫码打卡”。二维码不使用 URL，不负责自动打开小程序。起点只在未开始时接受，终点只在三个任务点完成后接受。二维码可以被拍照复制，因此只适用于当前低风险活动。

起点编号为 `000`，三个任务点仍为 `001`、`002`、`003`，终点为 `999`。五个点位的HRQ1数据保持原值，仅新版打印内容增加提示行。完整制作原文参见 `specs/004-start-finish-qr-timing/qr-payloads.md`。本次活动已同步更新云函数 ACTIVITY_CONFIG，部署后需从新起点开始联调。

总用时 = 终点扫码时间 - 起点扫码时间，格式为 `HH:mm:ss`，包含行进、拍照和停留时间。关闭页面不暂停计时，重复扫码不修改时间；第三个任务点照片上传完成后仍需扫描终点，不会直接生成凭证。时间取自手机时钟，不具备可信成绩或防改时能力。

新路线使用 `patchwalk-progress-v4-route-20261011`，从起点重新开始。旧v2/v3记录和照片不删除、不混入新成绩；新页面不展示旧进度。

本方案只提供本机层面的防误用校验。二维码和本地 storage 都不能提供密码学防伪或可信考勤能力；清除小程序数据、重装或更换设备会丢失进度。

## 完赛人员名单与 Excel

MVP 保留本机打卡与凭证，启用的目标环境将昵称、活动/路线版本、完成点位和起止时间汇总至云开发数据库，照片和头像不上传。管理员用私有云账号权限在电脑生成 .xlsx，参与者看不到名单或导出入口。

开发版和体验版走独立测试环境，正式版走正式环境；正式活动设置时间窗口并排除开发/测试账号。旧凭证没有起点绑定的活动上下文，不会自动回填。正常账号在正式窗口用正式版测试无法自动识别，必须先列入排除账号。

本地代码已实现；当前路线固定使用 routeVersion=route-20261011-v1 和 routeId=route-20261011。测试环境为 cloud1-d1g886bht0f7cbf69，正式环境为 shnu-health-run-20261021-dc2d3ff；两端集合均为 finishers。活动编号统一为 health-run-2026-event02，活动名称为“步履拾光·健康同行”。日常重新编译、部署云函数、上传体验版或修复代码都不改变这些值；只有新路线或新活动才创建新标识。正式配置窗口为 2026-10-09 至 2026-11-09，补交至 11-10（Asia/Shanghai），并排除开发/测试账号。需同步对应云函数 ACTIVITY_CONFIG 后测试新名单；本地示例修改不会自动部署。正式版需发布后从起点重新开始。导出失败显示阶段与安全错误码，不输出凭据。收集范围不含实名，名单仅代表已收到的手机自报完赛摘要，不作为可信排名或到场证明。

管理员 SDK 访问返回 INVALID_ENV 时，可在云开发控制台导出 finishers 的全部字段 JSON，再执行 `bash tools/export-finishers/export-test.sh "$HOME/Downloads/finishers.json"` 本地转换为 Excel，无需 npm/密钥或云访问；文件路径替换为实际下载文件。转换仍排除异常和重复行，工作簿注明只包含输入文件内记录。导出原始 JSON 私有保存，若放仓库使用被 Git 忽略的 exports/。

建立云环境、部署 submitCompletion、设置 ACTIVITY_CONFIG、数据库权限及电脑导出操作，见 [完整部署说明](specs/005-finisher-list-export/deployment.md)。Spec-kit 任务与线上验收见 [tasks.md](specs/005-finisher-list-export/tasks.md)。
本轮按 [开发环境联调说明](specs/005-finisher-list-export/development-setup.md) 操作，无需先准备正式活动时间或排除账号。
